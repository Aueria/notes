## Purpose 

Introduces I2C communication on the STM32F405 using STM32CubeIDE, scanning I2C1 and I2C2 buses to detect devices (e.g., DF Robot 10DOF board), focusing on master-slave protocol and HAL usage.
## Steps

### Part 1: MCU Configuration

1. Configured debug interface:
    
    - Navigated to System Core > SYS.
        
    - Set Debug to Serial Wire (PA13 for SWDIO, PA14 for SWCLK).
        
    - Skipped Trace Asynchronous SW.
        
2. Configured I2C:
    
    - Navigated to Connectivity > I2C1, enabled I2C mode.
        
    - Navigated to Connectivity > I2C2, enabled I2C mode.
        
    - Navigated to GPIO, enabled pull-up for SCL/SDA lines (e.g., 4.7k or 10k external recommended).
        
3. Configured UART (optional):
    
    - Navigated to Connectivity > USART1, enabled Asynchronous mode.
        
    - Set baud rate to 921600.
        
    - Noted USART1 uses PA9 (TX), PA10 (RX).
        
4. Configured clock:
    
    - Navigated to System Core > RCC, set HSE to Crystal/Ceramic Resonator (16 MHz crystal).
        
    - In Clock Configuration, set input to 16 MHz, PLL: PLL_M = 8, PLL_N = 336, PLL_P = 2 (168 MHz system clock, APB1 timers at 84 MHz, APB2 at 168 MHz).
        
5. Clicked Generate Code.
    

### Part 2: UART Setup and Tick Loop

1. Added UART support:
    
    - In USER CODE BEGIN Includes, added:
        
        ```c
        #include <stdio.h>
        ```
        
    - In USER CODE BEGIN 0, added:
        
        ```c
        int __io_putchar(int ch) {
            HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, HAL_MAX_DELAY);
            return ch;
        }
        ```
        
2. Added startup message:
    
    - In USER CODE BEGIN 2, added:
        
        ```c
        printf("Starting I2C scan\n");
        ```
        
3. Added tick loop:
    
    - In USER CODE BEGIN PV, added:
        
        ```c
        uint32_t now = 0;
        uint32_t next_tick = 1000;
        uint32_t loop_count = 0;
        ```
        
    - In USER CODE BEGIN 3, added:
        
        ```c
        loop_count++;
        now = HAL_GetTick();
        if (now >= next_tick) {
            printf("Tick %lu seconds - Loop Count: %lu\n", (now / 1000), loop_count);
            loop_count = 0;
            next_tick = now + 1000;
        }
        ```
        
        Prints tick every second with loop count (~12M loops/sec with -Og).
        

### Part 3: I2C Bus Scan

1. Added I2C scan function:
    
    - In USER CODE BEGIN 0, added:
        
        ```c
        void i2c_scan(I2C_HandleTypeDef *hi2c, const char *bus_name) {
            printf("Scanning %s...\n", bus_name);
            for (uint8_t addr = 0; addr < 128; addr++) {
                if (HAL_I2C_IsDeviceReady(hi2c, (addr << 1), 1, 10) == HAL_OK) {
                    printf("Device found at 0x%02X\n", addr);
                }
            }
            printf("Scan complete\n");
        }
        ```
        
        Scans 7-bit addresses (0-127), shifts left for read/write bit.
        
2. Called scan in main:
    
    - In USER CODE BEGIN 2, added:
        
        ```c
        i2c_scan(&hi2c1, "I2C1");
        i2c_scan(&hi2c2, "I2C2");
        ```
        
3. Built and flashed:
    
    - Rebuilt and reflashed.
        
    - Observed serial output showing devices at 0x1E, 0x53, 0x68, 0x77 on I2C2 (from DF Robot 10DOF board).
        
    - No devices on I2C1 (or as per attached hardware).
        

## Observations

- I2C bus scan found devices at 0x1E (compass?), 0x53 (accelerometer?), 0x68 (gyro), 0x77 (pressure sensor) on I2C2.
    
- Tick loop showed ~12M loops/sec with -Og.
    
- I2C used open-drain SCL/SDA lines with pull-up resistors.
    
- 7-bit addresses shifted left for HAL functions.
    

## Troubleshooting

- No devices found: Verified SCL/SDA wiring, pull-up resistors (4.7k or 10k), I2C enabled in STM32CubeMX.
    
- No UART output: Checked USART1, PA9 to serial RX, 921600 baud.
    
- I2C errors: Ensured correct bus (I2C1 or I2C2), device addresses from datasheets.
