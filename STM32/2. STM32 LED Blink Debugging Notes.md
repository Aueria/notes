## Purpose 

Extends the non-blocking blink application by adding a loop counter and introducing debugging techniques using STM32CubeIDE’s debugger, focusing on breakpoints, stepping, and variable monitoring.
## Steps

### Part 1: Review and Enhance Blink Code

1. Opened existing Black_Pill_Blink_2 project in STM32CubeIDE.
    
2. Added loop counter:
    
    - In USER CODE BEGIN PV, added:
        
        ```c
        uint32_t loop_count = 0;
        ```
        
    - In USER CODE BEGIN 3 (inside while(1)), added:
        
        ```c
        loop_count++;
        ```
        
    - Inside 500 ms if-block, modified:
        
        ```c
        printf("Toggling GPIO - Loop Count: %lu\n", loop_count);
        loop_count = 0;
        ```
        
    - Inside 1000 ms if-block, modified:
        
        ```c
        printf("Tick %lu seconds - Loop Count: %lu\n", (now / 1000), loop_count);
        loop_count = 0;
        ```
        
3. Built and flashed:
    
    - Clicked Build (hammer icon).
        
    - Connected ST-Link: SWDIO to PA13, SWCLK to PA14, GND to GND, 3.3V to 3.3V.
        
    - Clicked Run (green play icon).
        
    - Observed LED toggling every 500 ms.
        
    - Serial output showed loop counts (~2.6M loops/sec, ~1.3M between toggles).
        

### Part 2: Debugging the Application

1. Launched debugger:
    
    - Clicked debug icon (bug symbol).
        
    - Flashed application, halted at first instruction in main() (auto-breakpoint).
        
    - Noted: LED not blinking, no new serial output during halt.
        
2. Stepped through code:
    
    - Used F5 (Step Into) to enter functions (e.g., HAL_Init()).
        
    - Used F6 (Step Over) to execute lines without entering functions.
        
    - Stepped through initialization until printf("Non-blocking blink starting\n"), observed serial output.
        
3. Resumed and suspended:
    
    - Clicked Resume (green play icon); LED blinked, serial output continued.
        
    - Clicked Suspend (pause icon); LED stopped, no new serial output.
        
    - Checked Variables view for locals (e.g., now, last_blink) at halt.
        
4. Used breakpoints:
    
    - Added breakpoints at HAL_GPIO_TogglePin and printf("Tick ...").
        
    - Resumed; halted at 500 ms breakpoint (e.g., now = 19500, last_blink = 19000).
        
    - Stepped with F6; observed LED toggle and serial print.
        
    - Continued to 1000 ms breakpoint (e.g., now = 20000).
        
    - Removed all breakpoints via Run > Remove All Breakpoints.
        
    - Added breakpoint at HAL_GetTick(), resumed, and stepped.
        
5. Monitored variables and expressions:
    
    - At halt, checked Variables tab for locals (e.g., now, last_blink, loop_count).
        
    - Added global uwTick to Expressions tab.
        
    - Removed breakpoints, resumed; observed uwTick updating live (~milliseconds since boot).
        
6. Ended debugging:
    
    - Clicked Terminate (red square icon) to end debug session; application continued running.
        

## Observations

- Debugging uses ARM JTAG/debug module; allows pausing and modifying without affecting core.
    
- Halting showed ~2.6M loop iterations/sec in non-blocking loop.
    
- Breakpoints and stepping revealed timing (e.g., 500 ms intervals).
    
- Live expressions tracked uwTick in real-time; Variables tab showed locals at halt.
    

## Troubleshooting

- No halt at main: Ensured debug config set (Serial Wire enabled in STM32CubeMX).
    
- Variables not showing: Halted in function with locals; globals used Expressions tab.
    
- Slow updates: Noted live expressions may lag; used for monitoring.
    
- ST-Link errors: Updated firmware; checked connections.
    
- Serial output during debug: Worked but paused with execution.
